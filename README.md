# green-chat

Минимальный веб-клиент для Telegram поверх [GREEN-API](https://green-api.com/telegram): создание чата по номеру телефона, отправка и получение текстовых сообщений. Тестовое задание на должность "Фронтенд-разработчик React".

Задание предлагало MAX, WhatsApp или Telegram. Выбран Telegram.

**Стек:** React 19, TypeScript, Vite, zustand, Vitest.

## Онлайн-версия

Задеплоинный вариант на Vercel: **[тут](https://green-chat-sigma.vercel.app/)**

На экране входа есть два варианта:
- **"Демо без GREEN-API"**: работает без аккаунта, собеседник отвечает автоматически (подробнее в разделе "Демо-режим").
- **Свои данные**: введите `apiUrl`, `idInstance` и `apiTokenInstance` своего инстанса GREEN-API (раздел "Как подключить настоящий аккаунт").

Данные остаются в вашем браузере и **никуда, кроме GREEN-API, не отправляются**.

## Быстрый старт

Нужен Node.js от 22 (проверено на 24.0.0).

```bash
npm install
npm run dev
```

Без аккаунта GREEN-API можно сразу нажать **"Демо без GREEN-API"** на экране входа. Там работает мок с теми же правилами очереди, что и у настоящего сервиса.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер |
| `npm run build` | проверка типов и production-сборка в `dist/` |
| `npm run typecheck` | только проверка типов |
| `npm test` | все тесты один раз |

## Как подключить настоящий аккаунт

1. Зарегистрируйтесь в [личном кабинете GREEN-API](https://console.green-api.com/registration) и создайте инстанс Telegram (бесплатный тариф Developer).
2. Авторизуйте инстанс аккаунтом Telegram: в приложении "Настройки → Устройства → Подключить устройство" и скан QR из кабинета. Для теста лучше взять отдельный аккаунт: через инстанс идут уведомления по **всем** чатам аккаунта.
3. В настройках инстанса включите получение входящих сообщений (`Получать уведомления о входящих сообщениях и файлах`) и оставьте `Адрес отправки уведомлений (URL)` **пустым**. После создания инстанса все настройки выключены, и без этого шага приложение будет молча получать пустые ответы.
4. Откройте приложение и введите `apiUrl`, `idInstance` и `apiTokenInstance` со страницы инстанса.
5. Нажмите "+", введите номер получателя в международном формате и пишите. Ответы появляются сами.

## Используемые методы GREEN-API

| Метод | Зачем |
| --- | --- |
| `GET getStateInstance` | проверка данных при входе и состояния инстанса |
| `POST checkAccount` | номер телефона → `chatId` (нужен один раз на чат) |
| `POST sendMessage` | отправка текста по `chatId` |
| `GET receiveNotification` | long polling входящих (ожидание 5 с) |
| `DELETE deleteNotification` | удаление обработанного уведомления |

В задании названы `SendMessage` и `ReceiveNotification`. Остальные три нужны, чтобы это работало:

- В Telegram-версии `chatId` числовой, а не номер телефона. Входящие приходят с числовым `chatId`, поэтому для привязки ответа к чату, созданному по номеру, нужен `checkAccount`. Дальше всё идёт только по `chatId`.
- Без `deleteNotification` очередь останавливается: следующий `receiveNotification` возвращает то же уведомление.

## Ограничения бесплатного тарифа Developer

- Обмен возможен только с **3 чатами**. При превышении сервис отвечает ошибкой 466, приложение показывает понятное сообщение.
- `checkAccount`: 100 вызовов в месяц, лимиты обновляются 1-го числа.
- Один инстанс Developer на кабинет.

## Хранение данных

- Данные для входа по умолчанию лежат в `sessionStorage` и пропадают при закрытии вкладки. С галочкой "Запомнить на этом устройстве" они сохраняются в `localStorage`. Токен в браузере хранится в открытом виде: используйте отдельный тестовый инстанс.
- Чаты и сообщения хранятся в `localStorage` отдельно для каждого `idInstance` (и отдельно для демо).
- Кнопка "Выйти" стирает данные входа и историю этого инстанса.

## Демо-режим

Кнопка "Демо без GREEN-API" подставляет мок вместо сети:

- любой корректный номер (8–15 цифр) создаёт чат, **кроме** номеров, оканчивающихся на `0`: их "нет в Telegram" (так можно увидеть ошибку);
- собеседник отвечает через 1–3 секунды;
- примерно через 8 секунд приходит сообщение от нового контакта (проверка автосоздания чата);
- в очереди лежат и служебные уведомления, которые приложение обязано удалять и игнорировать.

## Тесты

`npm run test`: 16 тестов на чистую логику без сети и браузера.

- `src/lib/notifications.test.ts`: разбор входящих уведомлений GREEN-API (текст, ссылки, служебные типы, имя отправителя).
- `src/store/chatState.test.ts`: редьюсеры состояния чатов (создание чата, дедупликация сообщений, непрочитанные, сортировка).

Клиент GREEN-API и интерфейс тестами не покрыты, они проверены вручную на реальном инстансе и в демо-режиме.

## Что не входит

По заданию только текст. Нет групп, файлов, редактирования и удаления сообщений, статусов прочтения, истории с сервера: список чатов и переписка хранятся локально.
